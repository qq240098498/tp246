# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、盯温度记录、算超限与断链、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5246（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期/即将到期/送检中的探头数、批次总数与各状态条数、温度记录条数与人工记录数、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、最高与平均 MKT、按冷库一行给出探头与批次数。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数），都带增改删。探头台账的状态只能手动置「在用/停用」；「送检」与「报废」由校准提醒页的送检流程管理，不能在表单里直接改。
- **校准提醒**：按校准有效期给出**已逾期**（带逾期天数，一直挂着不消失）、**即将到期**（提前天数在页面上直接改，设置里也有默认值 `calibrationWarnDays`）、**送检中**三组清单，每行带编号、所属冷库、位置、台账状态、校准状态、校准有效期、剩余/逾期天数、最近一次记录时刻与在途送检单。可登记送检（送检时刻、送检单位、预计返回日期、送检人），送检回来登记结果：**换证/复校**更新校准有效期并恢复在用；**不合格**按口径置「停用」或「报废」。登记结果时给出这趟涉及哪些批次（名下有该探头记录的批次），逐条列出四条放行判定里哪些结论发生了变化、放行总评是否翻转。下方是送检台账（每趟一张单）。
- **批次**：批次清单（批次号、品名、规格、件数、所在冷库、入库时刻、状态、温度记录条数、最长超限、累计超限、MKT、断链数、放行情况），行内展开逐条温度记录、超限段、断链缺口、放行判定五项与放行单，并提供「放行」「拒收」入口。
- **温度记录**：记录清单（批次、探头、时刻、温度、来源、登记人、是否超限），支持按批次与探头筛选、单条新增与删除。
- **放行台账**：放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、断链数与依据）。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **超限段**：按时刻顺序逐条判，连续超限的时段算一段，**中间只要有记录回到范围内就断开**；每段的时长按该段相邻记录的实际时刻差累加。
3. **累计超限**：一个批次从入库到当前，所有超限段的时长之和；**跨月不重置**，按批次周期累计。
4. **断链**：相邻两条记录的时刻差超过 `chainGapMinutes`（默认 15 分钟）算一处断链，缺口时长按实际时刻差算。
5. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与计算的记录条数）；**不是把温度取平均**。
6. **放行判定四条**：单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）、累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟）、全程没有断链、**参与判定的探头都在用且在校准有效期内**。四条同时满足才算满足放行条件；**没有任何温度记录的批次不能放行**（四条之外的硬门槛）。超限段、累计超限、断链都只按「参与判定的有效记录」计算。
7. **同一探头同一时刻既有自动记录又有手工更正记录时，以手工记录为准**；**停用、送检中、报废的探头，以及记录时刻校准已过期的探头，其名下记录不参与判定**（数据照常登记留痕，并在批次详情里逐条标出原因）。
8. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。
9. **校准提醒**：校准有效期当天仍有效，次日起算「已逾期」；到期前 `calibrationWarnDays` 天（默认 30，设置里可改、校准提醒页上可临时改）起算「即将到期」。已逾期且未处理的探头**每次打开页面都在清单里挂着**，逾期天数按天增长，不会提醒一次就消失；报废探头不再出现在清单。
10. **送检口径**：登记送检后探头状态为「送检」，送检期间其记录不参与放行判定（与停用一致），期间到达的记录仍登记留痕、放行第四条会点名该探头；一支探头同时只能有一张未闭环的送检单。回来登记结果：
    - **换证 / 复校**：填入新校准有效期（换证可登记新证书号），探头恢复「在用」，自新有效期起重新计算提醒；
    - **不合格**：登记处理口径「停用」（可整改后重新送检）或「报废」（永久不参与判定、不再挂提醒、不能再送检）。
    
    登记送检与登记结果都会返回**本趟涉及的批次**（名下有这支探头记录的批次，含已放行/已拒收），并按「送检前 vs 登记后」的口径重算放行判定，列出哪些判定结论发生了变化（满足↔不满足）、四条总评是否翻转；送检单与结果都留在送检台账。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改（状态只能在用/停用）/ 删除（有记录或送检单的不能删） |
| GET | /api/calibration/watch | 校准提醒清单（bucket：open/overdue/dueSoon/sent/all，warnDays 可临时覆盖设置，roomId、status），含逾期天数、最近记录时刻、在途送检单 |
| GET | /api/calibrations | 送检台账（支持 probeId、open=1） |
| POST | /api/probes/:id/send-calibration | 登记送检，body `{sentAt, lab, expectedReturnAt, sender, remark}`，返回探头与本趟涉及批次的判定变化 |
| POST | /api/calibrations/:id/return | 登记送检结果，body `{returnedAt, result: 换证|复校|不合格, newCalibratedUntil, certificateNo, failAction: 停用|报废, receiver, resultRemark}`，返回更新后探头与涉及批次的判定变化 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含记录、超限段、断链、放行单）/ 修改 / 删除 |
| GET | /api/batches/:id/release-check | 这个批次的放行判定 |
| POST | /api/batches/:id/decision | 放行或者拒收，body `{decision, decider, decidedAt, basis, remark}` |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、from、to）/ 新增 |
| DELETE | /api/records/:id | 删除一条记录 |
| GET | /api/releases | 放行台账（支持 batchId、decision） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
